3.3 State Management & "Lifting State Up" Pattern

State flows unidirectionally from parent to children. In HomePage.tsx, the wishes state is lifted up to allow <SendWishes /> to submit new entries while <Wishes /> displays them reactively without external Redux/Zustand overhead. 

// src/pages/HomePage.tsx
export default function HomePage() {
  const [wishes, setWishes] = useState<Wish[]>(INITIAL_WISHES);

  // Callback passed downward to child component
  const handleNewWish = (wish: Wish) => {
    // Functional updater ensures immutable array prepending
    setWishes((prev) => [wish, ...prev]);
  };

  return (
    <main>
      <Wishes wishes={wishes} />
      <SendWishes onSubmit={handleNewWish} />
    </main>
  );
}

3.4 Custom Hook: useCountdown & Timer Lifecycle Management

To decouple complex countdown mathematics from UI presentation, a custom hook was designed. It calculates days, hours, minutes, and seconds relative to the event date and manages an active setInterval with proper cleanup to prevent memory leaks. 

// src/hooks/useCountdown.ts
import { useState, useEffect, useCallback } from 'react';

interface CountdownValues {
  days: string;
  hours: string;
  minutes: string;
  seconds: string;
  isExpired: boolean;
}

export function useCountdown(targetDate: Date): CountdownValues {
  // useCallback memoizes the calculation function
  const calculate = useCallback((): CountdownValues => {
    const now = new Date().getTime();
    const target = targetDate.getTime();
    const diff = target - now;

    if (diff <= 0) {
      return { days: '00', hours: '00', minutes: '00', seconds: '00', isExpired: true };
    }

    const days = Math.floor(diff / (1000 * 60 * 60 * 24));
    const hours = Math.floor((diff % (1000 * 60 * 60 * 24)) / (1000 * 60 * 60));
    const minutes = Math.floor((diff % (1000 * 60 * 60)) / (1000 * 60));
    const seconds = Math.floor((diff % (1000 * 60)) / 1000);

    return {
      days: String(days).padStart(2, '0'),
      hours: String(hours).padStart(2, '0'),
      minutes: String(minutes).padStart(2, '0'),
      seconds: String(seconds).padStart(2, '0'),
      isExpired: false,
    };
  }, [targetDate]);

  const [countdown, setCountdown] = useState<CountdownValues>(calculate);

  useEffect(() => {
    const interval = setInterval(() => {
      setCountdown(calculate());
    }, 1000);

    // Critical Cleanup: clears interval on component unmount
    return () => clearInterval(interval);
  }, [calculate]);

  return countdown;
}

3.5 Direct DOM Interaction with useRef

React discourages direct DOM queries like document.getElementById(). The project utilizes typed useRef hooks for two distinct use cases:

  1. Media Playback: Controlling the HTML5 <audio> element in Music.tsx without re-rendering.
  2. Instance Variable Storage: Storing drag starting coordinates (dragStartX.current) in Schedule.tsx to calculate touch/swipe distance without triggering re-renders.
// src/components/Music.tsx
const audioRef = useRef<HTMLAudioElement | null>(null);

const toggleMusic = () => {
  if (!audioRef.current) return;
  if (isPlaying) {
    audioRef.current.pause();
    setIsPlaying(false);
  } else {
    audioRef.current.play()
      .then(() => setIsPlaying(true))
      .catch((err) => console.warn('Audio playback policy prevented autoplay:', err));
  }
};

To emulate physical inertia, easing curves are defined using cubic-bézier control points:

  • ease: [0.25, 1, 0.5, 1]: Decelerating ease-out curve for natural text reveals.

6.1 3D CSS Flip Card Mechanics

The 3D cards in the Countdown timer and Location ribbon rely on three fundamental CSS 3D properties: 

/* 1. Establish 3D perspective viewport */
.nce-card-container {
  perspective: 1000px;
}

/* 2. Preserve 3D space across parent and child */
.nce-card-inner {
  position: relative;
  width: 100%;
  height: 100%;
  transform-style: preserve-3d;
  transition: transform 0.85s cubic-bezier(0.34, 1.4, 0.64, 1);
}

/* 3. Hide reverse face when flipped */
.nce-card-front,
.nce-card-back {
  position: absolute;
  inset: 0;
  backface-visibility: hidden;
  -webkit-backface-visibility: hidden;
}

/* 4. Pre-rotate back face */
.nce-card-back {
  transform: rotateY(180deg);
}
How perspective Works
perspective: 1000px determines the simulated distance between the viewer's eye and the z=0 plane. Lower values exaggerate 3D distortion; 1000px delivers a subtle, realistic physical depth.
Role of backface-visibility
Without backface-visibility: hidden, when a card flips 180 degrees, the front face would show mirror-reversed instead of revealing the back face content.

7. Vite Build Engineering, Routing & CI/CD Pipeline

7.1 Subpath Asset Resolution (import.meta.env.BASE_URL)

Deploying to GitHub Pages means the application lives at a repository subpath: https://ganeshpoojary727.github.io/Code_Nimbus_Solutions__Assignment/.

Hardcoded root paths like /svg/star.svg fail because the browser requests them from the domain root. The project uses a centralized asset(path) helper: 

// src/utils/assets.ts

7.2 Why HashRouter Instead of BrowserRouter?

Architectural Interview Question

"Why did you choose HashRouter over BrowserRouter?"

GitHub Pages is a static web server without server-side rewrite rules (such as Nginx try_files $uri /index.html). If a user bookmarks or refreshes https://.../gallery with BrowserRouter, GitHub Pages looks for a physical directory named gallery/index.html and returns an HTTP 404 error.

HashRouter stores route state in the URL hash fragment (#/gallery). Browsers never send the hash portion to the web server, allowing React Router to intercept and render the route entirely client-side without requiring server reconfiguration.

9. Technical Interview Defense Cheatsheet

Common senior frontend interview questions and the exact architectural defense based on this codebase:

Q1: How did you ensure 60fps performance with so many concurrent animations?
All Framer Motion animations animate hardware-accelerated CSS properties: transform (such as scale, rotateY, y) and opacity. These properties do not trigger expensive browser layout recalculations or repaints. They are offloaded directly to the GPU compositor layer. Furthermore, lazy loading ensures heavy asset trees aren't competing for initial render cycles.
Q2: Why use a custom hook (useCountdown) instead of putting the timer inside the component?
Separation of concerns. The mathematical countdown calculation and interval lifecycle are pure business logic. Extracting them into useCountdown makes the logic unit-testable in isolation, highly reusable across different views, and prevents the CountDown.tsx UI component from being cluttered with interval timers and state math.
Q3: How does the AI Wish Generator work in SendWishes.tsx?
Inside src/data/content.ts, a curated set of heartfelt blessing templates (AI_WISH_TEMPLATES) is maintained. When the user clicks the "Generate AI Wish" button, handleGenerateAIWish selects a pseudo-random template using Math.floor(Math.random() * AI_WISH_TEMPLATES.length) and updates the controlled message state, instantly populating the textarea.
Q4: How did you avoid memory leaks with setInterval?
In React, unmounting a component while an interval is running leaves an orphaned timer in browser memory attempting to update unmounted component state. In useCountdown.ts, the useEffect returns a cleanup closure: return () => clearInterval(interval);. React automatically executes this cleanup function whenever the component unmounts or before re-running the effect.
Q5: How does swipe/drag work in Schedule.tsx without external gesture libraries?
I implemented a lightweight pointer tracking system using React synthetic touch and mouse events (onTouchStart, onTouchEnd, onMouseDown, onMouseUp). A useRef<number | null>(null) stores the initial client X coordinate without triggering component re-renders. On touch/mouse release, the delta is measured against a 40px threshold to trigger forward or backward timeline progression.
Q6: What is the purpose of Oxlint in this project?
Oxlint is an ultra-fast, Rust-based JavaScript and TypeScript linter that runs 50 to 100 times faster than legacy ESLint. It caught dead imports and unused variables instantly during development, ensuring that our final codebase had zero warnings and zero dead dependencies before submission.
Q7: How did you handle browser autoplay audio restrictions in Music.tsx?
Modern browsers prohibit programmatic audio playback without prior user interaction. In Music.tsx, instead of attempting forbidden autoplay on mount, an explicit user-interactive floating toggle button was created. The playback call catches any browser rejection gracefully: audioRef.current.play().catch(err => console.warn(err)).
